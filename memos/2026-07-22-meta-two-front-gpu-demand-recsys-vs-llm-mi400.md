- **Thesis frame (the useful insight)**: Meta has **two distinct GPU-demand fronts with opposite hardware requirements**, and the SA-vs-practitioner debate is really about which one Meta should optimize for. **(1) 搜广推 / recsys** (search, ads, recommendation — Meta's core money engine): the workload that is **actually GPU-short right now**, and it wants **memory-bandwidth-per-dollar + a higher CPU:GPU ratio + *less* total HBM/compute**. **(2) LLM (training + inference)** at Meta Superintelligence Labs (MSL / "TBD Lab", Alexandr Wang): wants **maximal HBM + compute**, and general LLM GPUs are **poorly suited to recsys**. Meta's custom AMD MI400 is a deliberate bet on front (1) — which is why SA calls it a "disaster for LLM" while practitioners call SA wrong ("现在就是搜广推缺卡" — it's recsys that's short on cards).
- ## The Meta Custom AMD MI400 (as SA describes it, per the chat)
	- | Spec | Standard MI455X | **Meta custom MI400** |
	  |---|---|---|
	  | Relative die size | 1× | **~½** |
	  | HBM capacity | 432 GB | **144 GB (~⅓)** |
	  | HBM stacks | 12× HBM4 **12-Hi** | **6× HBM4 8-Hi** (config cut in half) |
	  | Optimization target | general (LLM train/infer) | **recsys** — cost + memory-bandwidth-per-unit |
	- **Design rationale (SA)**: Meta's recsys infra team wants to **tune the CPU-compute : GPU-compute ratio** to better fit recommendation workloads and **optimize cost per unit of memory bandwidth** — hence the smaller die, ~⅓ the HBM capacity, and thinner 8-Hi stacks.
	- **SA's bear framing**: the SKU may be **fine for recsys but poor for LLM inference/training**; worse, the decision was made **before TBD Lab (MSL) existed**, so **Alexandr Wang's team had no input**, and because compute + HBM are both cut, the SKU is **less attractive to TBD Lab engineers** (a talent-recruiting negative). Headline: "billions wasted / disaster-level mistake."
- ## The Practitioner Pushback (the chat's counter)
	- **"SA is wrong" / SA傻逼**: the cut-down custom chip is *fit-for-purpose*, not a blunder. **"现在就是搜广推缺卡"** — right now it is **search/ads/recommendation that is GPU-constrained**, i.e., Meta's core revenue engine, not LLM.
	- **General LLM GPUs are the wrong tool for recsys**: "那些卡的 GPU/CPU 比都不适合搜广推" — the high-GPU/low-CPU, HBM-maximal ratio of LLM cards is **mismatched to recsys**, which is memory-bandwidth-bound and needs more CPU-side compute.
	- **Why rent LLM GPUs to Anthropic** (the user's question, "为啥 zuck 还要租 gpu 给 anthropic?"): precisely *because* those LLM-optimized cards are **not ideal for recsys anyway** — so leasing that capacity out (the compute-toll-booth from [[2026-07-13-semianalysis-meta-superintelligence-1yr-update]]) is rational while Meta builds custom recsys silicon for its core workload.
	- **The open question the chat lands on**: does LLM actually help Meta's core business? "市场明明还在等 LLM 帮到 Meta 核心业务" — the market is *still waiting* for LLMs to lift the money engine. How? "AI-generate 广告" (AI-generated ads) **and** "搜广推质量" (search/ads/rec *quality*). That is the crux: recsys silicon monetizes today; LLM's contribution to the core is still prospective.
