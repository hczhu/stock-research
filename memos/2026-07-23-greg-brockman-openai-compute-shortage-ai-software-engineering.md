- ## Greg Brockman on OpenAI, Software Engineering, and Compute
	- **Source**: Tae Kim ([@firstadopter](https://x.com/firstadopter)), brief notes from a July 23, 2026 reporter Q&A with OpenAI cofounder and president Greg Brockman at OpenAI's New York City office.
	- **Thesis**: Brockman's comments frame AI as a compounding supply-and-demand system: OpenAI has reorganized itself into a repeatable model-production engine, better interfaces are unlocking more uses, and realized customer ROI is pulling compute demand forward faster than capacity can expand. In software, the bottleneck is moving from writing code toward deciding what to build, exercising taste, and giving agents feedback—not toward less work.

- ## OpenAI's Model-Production System
	- Brockman said he feels very good about the models OpenAI has been releasing and described the company as a **“humming machine”** that is now turning out great models.
	- He attributed this cadence to rearchitecting how OpenAI works and conducts research.
	- The important signal is organizational, not a single model launch: OpenAI believes it has made frontier-model development more repeatable.
	- Brockman described AI capabilities as continuing to rise exponentially and said AI tools are unlocking substantial human ingenuity.
	- He also cautioned that **“AI is surprising,”** with strengths and weaknesses that differ from prior expectations. Capability progress is therefore unlikely to arrive evenly across tasks.

- ## Product Value Extends Beyond Raw Model Intelligence
	- Brockman argued that value comes not only from the raw intelligence of a model but also from how people interact with it, citing voice mode as an example.
	- This makes interface design, multimodality, context, and feedback loops part of the effective capability available to users.
	- A model can become more economically useful without a proportional increase in benchmark intelligence if a better interface makes existing capability easier to access and apply.

- ## Software Engineering Moves Up the Abstraction Stack
	- Software engineers increasingly spend their time **dreaming up what an application should do**, then providing feedback and taste while AI agents handle more implementation.
	- Brockman rejected the idea that this makes the job shallow: there is much more depth to software engineering than writing code.
	- Engineers using coding agents are, in his observation, **working harder than ever before**.
	- This supports an expansionary productivity model in which cheaper code raises ambition and output rather than simply reducing labor hours.
	- Human differentiation shifts toward judgment, product intent, taste, values, and the ability to recognize whether an output is actually good.
	- Brockman's broader claim is that greater machine capability exposes more human complexity rather than reducing people to interchangeable task execution.

- ## The Compute-Powered Economy
	- **Prediction**: **“The compute shortage will continue.”**
	- Brockman went further: **“My prediction is … we will remain in this compute shortage no matter what.”**
	- His rationale is demand elasticity. The economy is shifting toward work amplified by AI models, and users are seeing enough ROI to keep consuming additional intelligence as more compute becomes available.
	- Compute therefore becomes an input into labor and economic output, not merely a cost center for model training.
	- If this view is correct, efficiency improvements do not end infrastructure demand; they lower the cost of useful AI work and stimulate more usage.
	- The claim is structurally supportive of accelerator, memory, networking, power, and data-center demand, but the Q&A supplied no capacity, spending, pricing, or timing data with which to size that demand.

- ## Public-Market Relevance
	- **[[$NVDA]] and the AI infrastructure chain**: persistent compute scarcity supports continued demand for accelerators and the systems around them. The key source-derived point is that OpenAI expects realized ROI to absorb incremental supply, not that any specific vendor is guaranteed pricing power.
	- **[[$MSFT]]**: OpenAI's improving model cadence and growing compute intensity can increase the value of distribution and cloud capacity tied to OpenAI. The notes contain no new disclosure about Microsoft's economics, capacity commitments, or revenue share.
	- **Developer tools and software platforms**: value should migrate from manual code entry toward agent orchestration, specifications, review, testing, observability, and repositories that preserve context. More software output can expand machine activity even if traditional per-seat workflows weaken.
	- **Application companies**: raw model intelligence is only one source of differentiation. Products that improve interaction quality, capture user feedback, or encode domain-specific taste can turn common model capability into more useful outcomes.

- ## Source Limits
	- These are a reporter's brief notes rather than a full transcript, financial disclosure, or measured customer study.
	- The source provides no quantitative evidence for model-release velocity, coding productivity, ROI, compute demand, or the duration of the predicted shortage.
	- Treat the comments as a high-level statement of OpenAI management's operating confidence and demand expectations, not as stand-alone evidence for a forecast.
